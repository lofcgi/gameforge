# 용어집

> 문서 유형: 참조

이 교육 자료에서 쓰는 용어의 뜻을 한곳에 모았어요. 각 용어는 여기 적힌 형태로만 써요. 저장소의 문서(`harness/`, `games/cat-angler/design/`)가 쓰는 말과 같게 맞췄어요.

## 하네스와 구성 요소

| 용어 | 뜻 |
|---|---|
| 하네스 | AI 코딩 에이전트가 따를 절차, 쓸 도구, 넘지 못할 차단 규칙을 묶은 틀이에요. 이 저장소에서는 `harness/` 폴더의 gameforge를 가리켜요 |
| gameforge | 이 저장소의 하네스 이름이에요. Claude Code 플러그인 형태예요 |
| `gf` | 하네스의 Python CLI(Command Line Interface, 명령줄 도구)예요. 생성, 후처리, 엔진 실행, 심사 준비를 맡아요. 코드는 `harness/tools/gf/`에 있어요 |
| 플러그인 | Claude Code에 스킬, 서브에이전트, 훅을 한 묶음으로 더하는 단위예요 |
| 스킬 | 특정 요청이 들어왔을 때 에이전트가 읽고 따르는 절차 문서예요. `harness/skills/<이름>/SKILL.md`에 있고 13개예요 |
| 서브에이전트 | 메인 세션이 따로 띄우는 에이전트예요. 자기만의 맥락에서 일하고 결과만 돌려줘요 |
| 훅 | 에이전트가 도구를 쓰기 직전에 실행되어 그 행동을 막을 수 있는 스크립트예요. `harness/hooks/guard.py`예요 |
| 템플릿 | `gf init`이 복사하는 게임 프로젝트의 뼈대예요. `harness/templates/`에 네 개 있어요 |
| 브리지 | 게임 안에 들어가서 `gf`의 입력을 받고 게임 상태를 돌려주는 파일이에요(`gf/gf_bridge.gd` 또는 `gf/bridge.js`). 게임 쪽에서 고치지 않아요 |

## 사람과 에이전트

| 용어 | 뜻 |
|---|---|
| 사용자 | 게임을 기획하고 결과를 승인하는 사람이에요 |
| 메인 세션 | 사용자와 직접 대화하는 Claude Code 세션이에요. 일을 나누고 결과를 합쳐요 |
| 제작 에이전트 | 메인 세션이 작업 일부를 맡긴 서브에이전트예요 |
| 심사자 | 블라인드 심사를 하는 서브에이전트(`blind-judge`)예요. 화면 두 장과 심사 기준만 읽어요 |
| 작업 지시서 | 메인 세션이 제작 에이전트에게 주는 글이에요. 목표, 소유 범위, 실행해서 확인할 것, 보고 형식을 담아요 |
| 계약 문서 | 여러 에이전트가 따로 만든 결과가 맞물리도록 경로, 크기, 출력 형식을 미리 정한 문서예요. 예: `harness/AGENTS.md`, `games/cat-angler/design/asset-spec.md` |
| 미확인 목록 | 보고서에서 "실행해서 확인하지 못한 것"을 따로 모은 목록이에요 |

## 단계와 산출물

| 용어 | 뜻 |
|---|---|
| 단계 | 하네스가 나눈 제작 순서예요: `plan → look → graybox → assets → polish → publish` |
| 단계 승인 | 사용자가 한 단계의 결과를 보고 다음 단계로 넘어가도 된다고 하는 일이에요. 명령은 `gf state approve`예요 |
| 설계 요약 | 게임의 한 문장 소개, 핵심 반복, 닫힌 결정을 적은 문서예요. `design/brief.md`예요 |
| 레퍼런스 | 화면의 방향을 잡으려고 모은 참고 이미지예요 |
| 피할 예시 | "이런 느낌은 아님"으로 고른 레퍼런스예요. 명령에서는 `--anti`예요 |
| 모음판 | 여러 이미지에 번호를 붙여 한 장으로 만든 그림이에요. 사용자가 번호로 고를 때 써요 |
| 쏠림 경고 | 고른 레퍼런스의 대부분이 한 작품이나 한 사이트에서 왔을 때 `gf ref pick`이 내는 경고예요 |
| 기준 화면 | "이 게임은 이렇게 보여야 한다"를 고정한 그림 한 장이에요. 이후 모든 에셋과 블라인드 심사의 목표예요. cat-angler에서는 `design/look/target.png`예요 |
| 아트 디렉션 | 기준 화면을 글과 숫자로 풀어 쓴 문서예요(팔레트, 크기, 선, 움직임, 하지 말 것). `design/art-direction.md`예요 |
| 그레이박스 | 그림 없이 도형만으로 만든, 처음부터 끝까지 플레이할 수 있는 빌드예요 |
| 컷신 | 플레이 사이에 이야기를 보여 주는 장면이에요 |

## 에셋

| 용어 | 뜻 |
|---|---|
| 에셋 | 게임에 들어가는 그림, 소리, 모델이에요 |
| 원본 | 생성 모델이 내놓은 그대로의 파일이에요. `assets/raw/`에 둬요 |
| 게임용 에셋 | 후처리를 끝내 게임 코드가 읽는 파일이에요. `assets/game/`에 둬요 |
| 후처리 사슬 | 원본을 게임용 에셋으로 바꾸는 명령의 순서예요. 픽셀 아트는 크로마 → 격자 맞춤 → 팔레트 적용 → 검사예요 |
| 크로마 | 단색 배경을 투명하게 빼는 처리예요(`gf post chroma`) |
| 격자 맞춤 | 픽셀 아트처럼 보이는 큰 그림을 실제 게임 해상도의 픽셀 격자로 줄이는 처리예요(`gf post pixel-snap`) |
| 1배 | 확대하지 않은, 게임 해상도 그대로의 크기예요 |
| 팔레트 | 게임이 쓰는 색의 목록이에요. cat-angler는 24색이에요 |
| 스프라이트 시트 | 애니메이션 프레임을 한 장에 모은 그림과 그 좌표 파일이에요(`gf post sheet`) |
| 이음매 | 반복 재생하는 음악의 끝과 처음이 만나는 지점이에요 |
| 역할 | 생성 모델을 부르는 이름이에요(예: `image.concept`). 실제 모델 ID는 설정 파일이 정해요 |

## 검증

| 용어 | 뜻 |
|---|---|
| 자가 실행 | 에이전트가 게임을 직접 실행해서 스크린샷과 상태를 얻는 검증이에요 |
| 스모크 테스트 | 부팅, 첫 화면, 콘솔 오류, 입력 반응을 보는 가장 기본적인 자가 실행이에요(`gf engine test`) |
| 플레이 봇 | 실제 입력 경로로 게임을 플레이하는 프로그램이에요(`gf engine bot`). 정해 둔 입력을 그대로 넣는 고정 입력과, 상태를 보고 판단하는 정책 두 가지가 있어요 |
| 블라인드 심사 | 화면 두 장을 무작위 순서로 섞어, 제작 과정을 모르는 심사자에게 어느 쪽이 나은지 묻는 검증이에요 |
| 사람 플레이 | 사용자가 직접 플레이해서 재미, 조작감, 소리를 판정하는 검증이에요 |
| 근거 규칙 | "실행해서 본 것만 말한다"는 규칙이에요. 변경 뒤에 돌린 결과 파일이 있어야 "고쳤다"고 말할 수 있어요 |

## 비용

| 용어 | 뜻 |
|---|---|
| 추정 비용 | 생성 호출 전에 단가로 계산한 값이에요. 실제 청구액과 다를 수 있어요 |
| 비용 기록 | 생성 호출마다 한 줄씩 남는 기록이에요. 게임 폴더의 `.gf/ledger.jsonl`이에요 |

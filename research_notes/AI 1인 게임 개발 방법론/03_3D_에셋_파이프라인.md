## 1. 지난 한 달, 게임용 캐릭터/소품/환경에 어떤 도구가 최선으로 꼽히는가? 기간 내 신규 릴리스는?

### Takeaway
기간 내 확인된 변화는 "새 지오메트리 모델"이 아니라 **파이프라인 후반부(텍스처·리깅·토폴로지·자동화)의 보강**이다: Meshy N1 네이티브 텍스처링, Meshy의 quadruped 리깅과 `mixamo`/`ue5_mannequin` 스켈레톤 템플릿, Rodin의 프롬프트 편집형 리깅, Hi3D V1.0(구 Sparc3D) 오픈소스 공개. 어느 도구가 "최선"인지에 대한 기간 내 독립 실무자 평가는 찾지 못했고, 순위 근거는 벤더 자체 벤치마크뿐이다.

### Cited Findings

**Meshy (기간 내 가장 활발하게 업데이트됨)**

### Inferences
- 기간 내 릴리스 방향을 보면 벤더 경쟁 축이 "형상 품질"에서 "엔진 호환 리그(Mixamo/UE5 mannequin 스켈레톤), 텍스처 청결도, 토폴로지 제어"로 이동했다. 이는 형상 생성 자체보다 그 뒤 단계가 게임 투입의 병목이라는 벤더들의 인식을 반영한다(추론).
- Meshy가 T1(lowpoly)을 접고 Smart Topology(`meshy-t2.5`, polycount 지정)로 통합한 것은 "저폴리 전용 모델"보다 "목표 폴리곤 수를 지정하는 토폴로지 모델"이 표준이 되고 있음을 시사한다(추론).
- N1은 base color 전용·2K이므로 PBR이 필요한 사실적 에셋보다 **스타일라이즈드/핸드페인티드 계열**에 맞는 도구다. Meshy 자신도 "stylized game asset test set"으로 평가했다.

## 2. 구체적 단계별 워크플로와 수작업이 남는 지점

### Takeaway
기간 내 자료로 **API/제품 수준에서 조립 가능한 흐름**(이미지 → 메시 → Smart Topology → 텍스처 → 리그(엔진 스켈레톤) → 애니메이션 → GLB/FBX)은 확인되지만, 이를 실제로 돌려 게임에 넣은 실무자의 기간 내 단계별 기록은 찾지 못했다. 수작업이 남는 지점은 벤더 문서의 제한 사항과 2차 정리에서 간접적으로만 드러난다.

### Cited Findings
- **조립 가능한 Meshy 단일 벤더 흐름**(기간 내 changelog 기준): Image to 3D(`ai_model: meshy-7.1`, `texture_model` 선택) → Smart Topology(`meshy-t2.5`, `target_polycount`) → Retexture(`meshy-n1` 2K base color 또는 `meshy-7`) → Rigging(`skeleton_template: mixamo | ue5_mannequin`, `include_fingers`, `animation_type: quadruped`) → Animation. [공식][직접 확인] — [Meshy API changelog](https://docs.meshy.ai/en/api/changelog)
- 스크립트화: 2026-11-13 Meshy CLI 문서 페이지 신설(설치, 로그인, `meshy make` 명령). [공식][직접 확인] — [Meshy API changelog](https://docs.meshy.ai/en/api/changelog)
- **리그 단계의 함정**: Rigging에 `texture_image_url`을 넘기면 PBR 맵이 사라진다(2026-10-23 deprecated). [공식] — [Meshy API changelog](https://docs.meshy.ai/en/api/changelog)
- **포맷 선택**: GLB는 머티리얼과 애니메이션을 유지하고 OBJ·STL은 유지하지 않는다. 리깅을 더 요청하기 전에 뷰어에서 리그와 클립을 확인하라는 권고. [2차] — [Cinevva timeline, 2026-11-21 갱신](https://app.cinevva.com/guides/ai-3d-model-generation-timeline-2026)

## 3. 많은 에셋에 걸친 아트 스타일 일관성 유지 방법

### Takeaway
기간 내 3D 전용 스타일 일관성 기법(LoRA, 스타일 참조 워크플로)에 대한 실무자 자료는 찾지 못했다. 확인된 것은 (a) 참조 이미지 기반 리텍스처링이라는 제품 기능과 (b) "스타일 바이블/스타일 시트를 고정하고 벗어난 배치는 버린다"는 2D 중심 사례뿐이다.

### Cited Findings
- Meshy N1 Retexture는 텍스트 프롬프트 없이 **참조 이미지 1~4장**으로 텍스처를 입힌다 — 동일 참조 이미지 세트를 여러 메시에 재사용하는 방식의 일관성 수단이 된다(기능 사실; 일관성 효과 자체는 미검증). [공식] — [Meshy API changelog, 2026-11-02](https://docs.meshy.ai/en/api/changelog)
- Meshy는 N1을 "stylized game asset test set"에서 평가했다고 밝힘 — 벤더 스스로 스타일라이즈드 게임 에셋을 주 용도로 상정. [벤더 주장] — [Meshy blog, 2026-11-03](https://www.meshy.ai/blog/meshy-n1-texture)
- *Captive 3000* 사례: Claude로 style bible 작성 → 고정된 style sheet로 이미지 생성 → 스타일 벗어난 배치 폐기. 편집자 주: "Keeping one visual style across dozens of assets is the hardest part of AI art." 레트로 Amiga/Atari ST 풍을 택함. [2차, 2026-11-05] — [Creators' AI](https://thecreatorsai.com/p/how-to-build-a-game-with-an-ai-a)

### Inferences
- base color 전용 2K 텍스처(N1), 저폴리/Smart Topology, 레트로·스타일라이즈드 선택은 모두 PBR 정합성·미세 디테일 오류가 드러나는 사실적 스타일을 피하는 방향이다. "아티팩트를 숨기는 스타일을 고른다"는 전략과 부합하지만, 이를 명시적으로 권하는 기간 내 실무자 글은 확인하지 못했다(추론).
- 컨셉 이미지 단계에서 스타일을 고정(스타일 시트 + 동일 참조)하고 3D 생성기는 그 이미지를 따르게 하는 구조가 가장 통제하기 쉽다(추론).

### Gaps
- 3D 에셋용 LoRA·스타일 참조 워크플로, 셰이더(toon/outline)로 통일감을 주는 방법, 팔레트 고정 텍스처 기법 등에 대한 기간 내 자료 없음.
- 수십~수백 에셋 규모에서 일관성을 유지한 실제 3D 프로젝트 사례 없음.

## 4. 현실적 품질 한계 — AAA급 접근 가능성, 토폴로지·폴리 예산·LOD·성능

### Takeaway
기간 내 "신뢰할 만한 실무자"의 품질 한계 평가는 찾지 못했다. 확인 가능한 수치는 벤더가 밝힌 출력 상한과 제한 사항이며, 이것들은 **단일 에셋의 중간 폴리 게임 메시 수준**을 가리키지 AAA 파이프라인(수작업 리토폴로지, LOD 체인, 4K+ PBR 세트)을 대체한다는 근거는 아니다.

### Cited Findings
- 텍스처 상한: Meshy N1은 2K·base color 전용, PBR 맵·4K/8K 없음. [공식] — [Meshy blog, 2026-11-03](https://www.meshy.ai/blog/meshy-n1-texture)
- 리그 범위: Meshy는 biped + quadruped, 손가락 본 옵션, Mixamo/UE5 mannequin 스켈레톤. Rodin은 사람·동물·판타지 크리처와 텍스트로 기술한 커스텀 본(꼬리·귀). 페이셜 리그 언급은 두 changelog 모두 없음. [공식] — [Meshy API changelog](https://docs.meshy.ai/en/api/changelog), [Hyper3D changelog](https://hyper3d.ai/changelog/type/feature)
- 환경 메시 한계: Marble high-quality mesh는 구멍, 불균일한 지오메트리, floater가 생길 수 있고 얇거나 복잡한 구조·투명/반사 표면·하늘과 배경·입력 뷰가 덜 덮인 영역에서 두드러진다. 텍스처 버전 약 600k triangles(100~200 MB). [공식, 날짜 미상] — [World Labs docs](https://docs.worldlabs.ai/marble/export/mesh)
- 평가 태도에 대한 권고: 더 큰 메시나 더 새로운 릴리스가 로딩·변형·런타임 성능이 낫다는 증거는 아니며, 내보낸 에셋을 실제 씬에서 판단해야 한다. 작성 주체(Cinevva)는 3D 도구 벤더이며 스스로 독립 품질 벤치마크가 아니라고 밝힘. [2차] — [Cinevva timeline, 2026-11-21 갱신](https://app.cinevva.com/guides/ai-3d-model-generation-timeline-2026)
- 오픈 모델 하드웨어: TRELLIS.2 upstream은 NVIDIA GPU 메모리 24 GB 이상을 요구. [2차] — [Cinevva timeline, 2026-11-21 갱신](https://app.cinevva.com/guides/ai-3d-model-generation-timeline-2026)
- Hi3D V1.0은 1536³ 해상도 지오메트리를 내세우지만 텍스처는 생성하지 않는다. [공식 + 2차] — [PR Newswire, 2026-10-23](https://www.prnewswire.com/news-releases/hi3d-v1-0-goes-open-source-the-first-production-validated-open-source-ai-3d-model-302917973.html), [Cinevva timeline](https://app.cinevva.com/guides/ai-3d-model-generation-timeline-2026)

### Inferences
- 기간 내 근거만으로는 "solo 개발자가 AI 파이프라인으로 AAA급 충실도에 접근했다"는 주장을 뒷받침할 수 없다. 벤더 수치(2K base color, 수만 face 단위 토폴로지 모델, 페이셜 리그 부재)는 스타일라이즈드·중저폴리 타깃에서 가장 설득력이 있다(추론).
- LOD 자동 생성에 대한 기간 내 벤더 발표는 확인되지 않았다. polycount를 지정해 같은 에셋을 여러 번 뽑는 방식(`target_polycount`, 기간 직전 추가)이 LOD 대용으로 쓰일 수 있으나 LOD 간 실루엣·UV 일관성은 검증되지 않았다(추론).

### Gaps
- 변형(deformation) 품질, 엣지 루프, 스키닝 웨이트 품질에 대한 기간 내 독립 평가 없음.
- 실제 게임에서의 드로콜·메모리·프레임 영향 측정치 없음.
- AAA 근접 가능성에 대한 현업 아티스트의 기간 내 발언 없음.

### 배경(기간 외)

## 5. 비용/가격과 라이선스·상업적 이용 조건

### Takeaway

[공식 + 2차] — [PR Newswire, 2026-10-23](https://www.prnewswire.com/news-releases/hi3d-v1-0-goes-open-source-the-first-production-validated-open-source-ai-3d-model-302917973.html), [Cinevva timeline](https://app.cinevva.com/guides/ai-3d-model-generation-timeline-2026)

### Inferences
- solo 개발자에게 실질적 비용 리스크는 단가보다 **모델 은퇴 일정**이다: `meshy-5` 은퇴(10-10), T1 종료(11-30), `meshy-7` 지오메트리 은퇴(12-31)가 3개월 안에 몰려 있어, API에 묶인 자동화 스크립트는 수시로 깨진다. 에셋을 일괄 생성한 뒤 동일 모델로 추가 생성해 스타일을 맞추기 어려워질 수 있다(추론).
- 한국 거주 개발자는 Hunyuan 계열 오픈 가중치의 지역 제한 여부를 반드시 원문으로 확인해야 한다(아래 배경 참조; 기간 내 1차 확인은 못함).

### Gaps
- Meshy, Tripo, Rodin의 **달러 기준 요금제와 플랜별 상업 이용 조건**을 기간 내 1차 자료로 확인하지 못했다.
- Steam의 AI 공개(disclosure) 정책에 대한 기간 내 변경·공식 발표는 찾지 못했다.

## 6. 이 파이프라인을 실제로 쓴 출시작·호평작

### Takeaway
**기간 내에 AI 3D 생성기(Meshy, Tripo, Hunyuan3D, Rodin 등)로 만든 에셋을 썼다고 확인되는 출시작·호평작은 한 건도 찾지 못했다.** 유일하게 확인된 기간 내 solo 출시 사례(*Captive 3000*)는 오히려 3D 모델링을 하지 않고 2D + 원근 트릭으로 우회했다.

### Cited Findings
- *Captive 3000*(solo 개발자 Twin): 1인칭 실시간 그리드 기반 SF 던전 크롤러, 2026-11-06 Steam 출시 예정으로 소개되고 무료 데모 제공. AI 도구 체인(Claude, ChatGPT, Grok, OpenArt, Canva, Suno, Cursor)을 썼지만 "no 3D modeler"이며 3D 모델링·리깅·애니메이션 소프트웨어와 엔진은 언급되지 않는다. [2차, 2026-11-05][직접 확인] — [Creators' AI](https://thecreatorsai.com/p/how-to-build-a-game-with-an-ai-a)
- 같은 글의 품질 메모: 평면 스프라이트는 깊이를 주기 전에는 "read as cardboard", PowerPoint 수동 기울이기는 규모가 커지면 느리다. [2차, 2026-11-05] — [Creators' AI](https://thecreatorsai.com/p/how-to-build-a-game-with-an-ai-a)

### Inferences
- 기간 내 유일한 solo 출시 사례가 3D 생성 파이프라인을 회피했다는 점은, 3D 생성이 여전히 solo 개발자에게 "출시까지 가는 가장 쉬운 길"이 아닐 수 있음을 시사한다. 다만 표본이 1건이라 일반화할 수 없다(추론).
- 벤더 발표는 풍부한데 출시작 증거가 없다는 비대칭 자체가 이 영역의 현재 상태에 대한 신호다: 도구 기능은 빠르게 늘지만, 그 결과가 플레이어에게 받아들여진 게임으로 이어졌다는 공개 증거는 기간 내에 확인되지 않는다(추론).

### Gaps
- *Captive 3000*의 실제 출시 여부, Steam 리뷰 수·평가는 확인하지 못했다(글은 출시 전날 게시).
- AI 3D 에셋을 쓴 게임의 Steam 평가·매출·플레이어 반응에 대한 기간 내 자료 없음.
- 포스트모템, Steam AI disclosure 문구에 도구명을 밝힌 사례를 찾지 못했다.

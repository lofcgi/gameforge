# 레퍼런스: 한 작품을 베끼지 않고 여러 출처의 특성을 고른다

레퍼런스는 방향을 잡는 용도다. 결과물은 "어느 게임처럼"이 아니라 **"이 팔레트 + 이 조명 + 이 카메라 거리"** 같은 특성 묶음이다. 특정 게임의 이름·캐릭터·아트·레벨·화면 구성은 재현하지 않는다.

## 명령

`$GF` = `uv run -q --project "${CLAUDE_PLUGIN_ROOT}/tools" gf --project "<게임 폴더 절대 경로>"`.
공통 규약: `${CLAUDE_PLUGIN_ROOT}/skills/gf-start/conventions.md` (아직 안 읽었으면 먼저 읽는다).

## 1. 모은다 (목표: 서로 다른 출처 3곳 이상에서 15~40장)

`design/brief.md` 를 읽고 사용자에게 묻는다: "화면 느낌으로 떠오르는 것이 있나요? 게임이 아니어도 됩니다(영화, 그림, 사진). 반대로 이렇게는 되고 싶지 않은 것도요."

```sh
$GF ref steam <appid 또는 상점 주소> --max 8                  # 공개 스크린샷
$GF ref frames <영상 주소 또는 파일> --count 12 --note "<볼 것>"   # 같은 간격. 대신 --every <초> 또는 --scene 0.3
$GF ref add <파일 또는 이미지 주소> ... --note "<볼 것>" --tags "<쉼표 구분>"
$GF ref add <이미지 주소> --source-url <실려 있던 페이지 주소> --title "<작가·작품>" --note "<볼 것>"
$GF ref add <파일> --anti --note "<왜 아닌지>"                 # '이런 느낌은 아님'
$GF ref status                                              # 보관함·고른 것 현황
```

- `--note` 에는 그 이미지에서 **무엇을 볼지**를 적는다 (조명만, 팔레트, 캐릭터 비율). 나중에 특성을 뽑는 기준이 된다.
- 한 게임의 스크린샷만 모으지 않는다. 게임 한 편에서는 8장 이하로 받고 다른 출처(다른 게임, 영화 스틸, 일러스트, 사진)를 섞는다.
- `--source-url` 을 주면 메타의 `source_url` 에 그 페이지가, `image_url` 에 이미지 주소가 남는다. `--title` 은 작가나 작품 이름을 알 때만 적는다(쏠림 판단이 사이트가 아니라 작품 단위가 된다). 지어내지 않는다.

### 자동 수집을 막는 사이트 (Pinterest, ArtStation 등)

이런 사이트는 `ref add <검색 페이지 주소>` 로 긁을 수 없다. 사용자의 Chrome 에서 Claude in Chrome 도구로 검색 결과를 읽고, 이미지 주소만 `ref add` 로 가져온다. 순서:

1. **느낌을 묻는다.** 위 질문의 답에서 분위기·소재·피하고 싶은 것을 받는다.
2. **검색어를 제안한다.** "스타일 단어 + 소재" 꼴로 한국어와 영어를 섞어 4~6개(예: `수채화 어촌 일러스트`, `cozy fishing village watercolor`). 사용자가 고르거나 고치게 한다.
3. **브라우저로 읽는다.** 절차, 페이지 스크립트, 지킬 선은 `${CLAUDE_SKILL_DIR}/browser-collect.md` 를 따른다. 읽기만 한다. 로그인 화면이 나오면 멈추고 사용자에게 직접 로그인해 달라고 한다.
4. **검색어마다 8~12장만 가져온다.** 이미지마다 실려 있던 페이지 주소(`--source-url`), 볼 것(`--note`), 태그(`--tags "<사이트>,<검색어>"`)를 붙인다.
5. 아래 2절부터 그대로 간다: 모음판 → 사용자가 고름 → 측정 → 글로 정리.

Chrome 도구를 쓸 수 없거나 사용자가 직접 고르고 싶어 하면, 사용자가 이미지 파일을 폴더에 내려받고 `$GF ref add <파일> ...` 로 넣는다.

## 2. 모음판을 만들어 보여 준다

```sh
$GF ref sheet
```

`files` 의 모음판 PNG(`inbox-01.png` …, 번호가 붙어 있다)를 Read 로 보고 절대 경로를 사용자에게 준다. 묻는다: "번호로 골라 주세요. ① 이런 느낌(각각 무엇이 좋은지 한마디) ② 이런 느낌은 아님."

## 3. 고른 것을 기록한다

메모가 같은 것끼리 묶어 실행한다. 번호는 방금 만든 모음판의 번호다.

```sh
$GF ref pick 3 7 12 --note "팔레트와 안개"
$GF ref pick 5 --note "카메라 거리"
$GF ref pick 9 14 --anti --note "채도가 너무 높다"
$GF ref unpick 7                 # 번호는 inbox 모음판 기준. picked 모음판 번호면 --set picked. 전부 빼려면 --all
```

**쏠림 경고**: 결과의 `warnings` 가 비어 있지 않으면(고른 것의 대부분이 한 작품·한 사이트) 그대로 진행하지 않는다. 경고 문장을 사용자에게 전하고, 그 작품에서 가져오려던 특성을 말로 적은 뒤 다른 출처(다른 사이트, 다른 작가·작품)에서 같은 특성을 가진 이미지를 더 모아 다시 고르게 한다. 경고를 없애려고 `--title` 을 꾸며 넣지 않는다. 경고가 사라진 뒤에 다음으로 간다.

고른 것은 5~12장, 안티는 2~5장이 적당하다.

## 4. 측정하고 읽는다

```sh
$GF ref sheet --set picked
$GF ref traits --colors 6
```

`traits` 는 `references/picked/traits.json` 과 `traits-palette.png`(팔레트 견본)를 만들고 팔레트·강조색·색온도·밝기·대비·채도, 안티와의 차이(`difference`)를 낸다. 견본과 picked 모음판을 Read 로 본다.

그다음 `references/picked/analysis.md` 를 쓴다. 측정값은 근거로만 쓰고, 고른 이미지를 직접 보고 쓴다. 30줄 안쪽:

- **공통 특성** (각각 어느 이미지에서 봤는지 번호와 함께): 팔레트와 색온도, 명암 구조(밝은 배경에 어두운 전경인지 등), 조명 방향과 종류, 선·외곽선, 형태 언어(둥근/각진), 질감 밀도, 카메라 거리와 각도, 화면에서 주인공이 차지하는 크기, UI 분위기.
- **안티에서 피할 것**: 측정 차이(`difference`)와 눈으로 본 차이.
- **출처별로 가져오는 것**: "A 에서는 색만, B 에서는 카메라만"처럼 나눠 적는다. 한 출처에서 세 가지 넘게 가져오고 있으면 쏠린 것이다.
- **가져오지 않는 것**: 고유 캐릭터, 로고, UI 배치, 레벨 구성.

## 5. 확인받는다

`analysis.md` 와 `traits-palette.png` 의 절대 경로를 주고 공통 특성 다섯 줄을 대화창에 요약한다. 사용자가 맞다고 하면 `gf-look` 으로 넘어간다. 이 스킬에서는 단계를 승인하지 않는다 (look 단계는 기준 화면과 아트 디렉션까지 끝나야 승인한다).

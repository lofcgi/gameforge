# 폴리시 체크리스트

수치는 출발점이다. 게임마다 다르므로 넣고 나서 사람이 플레이해 맞춘다. 한 번에 하나만 넣는다.

## 1. 손맛

**입력에 반응하지 않는 것은 버그다.** 먼저 `engine replay` 의 `inputs.unresponsive` 를 0 으로 만든다.

| 수단 | 출발 수치 | 주의 |
|---|---|---|
| 입력 지연 제거 | 누른 그 틱에 속도·상태가 바뀐다 | 가속 곡선이 너무 길면 "미끄럽다"고 느낀다 |
| 점프 관용 | 발판을 벗어난 뒤 0.08~0.12초까지 점프 허용, 착지 0.08~0.12초 전 입력 기억 | 플랫포머에서 "점프가 씹힌다"의 대부분 |
| 가변 점프 | 버튼을 빨리 떼면 낮게 | — |
| 히트스톱 | 타격 순간 4~6프레임 정지 | 고정 틱 기준으로 구현한다(벽시계 금지). 너무 길면 끊긴다 |
| 임팩트 플래시 | 맞은 대상을 1~2프레임 흰색, 화면 플래시는 약하게(약 40%) | 번쩍임이 잦으면 피로하다. 광과민 주의 |
| 화면 흔들림 | 2~6px(픽셀 게임은 1~2px), 0.1~0.2초, 감쇠 | 약한 것부터. 끄는 설정을 둔다 |
| 스쿼시·스트레치 | 점프·착지에 10~20% | 충돌 판정은 바꾸지 않는다(그리기만) |
| 파티클 | 착지 먼지, 타격 파편, 획득 반짝임 | 난수는 시드를 따른다 |
| 소리 | 모든 주 행동과 결과에 하나씩 | `gf-audio`. 같은 소리 반복은 높낮이를 조금씩 바꾼다 |
| 카메라 | 진행 방향으로 약간 앞서 보기, 부드럽게 따라가기 | 멀미 나지 않게. 픽셀 게임은 정수 좌표 |

연출은 **그리기와 소리만** 바꾸고 게임 규칙(판정, 위치)은 바꾸지 않는다. 그래야 봇과 재생이 그대로 맞는다. 정지·흔들림도 고정 틱으로 센다.

확인: 정지 스크린샷으로는 안 보인다. `--at 1.00,1.05,1.10,1.15` 처럼 촘촘히 찍어 실제로 일어나는지 보고, 느낌은 사람에게 묻는다.

## 2. 가독성

- 화면을 흑백·작게 봐도 주인공, 위험물, 목표가 구분되는가. (스크린샷을 Read 로 보고 판단한다.)
- 가장 밝고 채도 높은 색은 주인공·상호작용 대상·위험에만 쓴다. 배경은 채도와 대비를 낮춘다.
- 위험은 닿기 전에 예고한다(색, 깜빡임, 소리). 죽은 이유를 플레이어가 안다.
- 전경과 배경이 같은 디테일 밀도면 섞인다. 배경을 단순하게 한다.
- HUD 숫자가 실제 상태와 같고, 가장 중요한 하나가 가장 크다.
- 블라인드 심사의 `readability`, `ui_legibility` 항목과 이유를 본다.

## 3. 첫 1분

`$GF engine run --record` 로 **처음 하는 것처럼** 플레이해 달라고 하고(가능하면 다른 사람), 기록을 재생해 본다.

- 첫 화면에서 5초 안에 무엇을 누를지 아는가. 글 설명 없이 되는가.
- 첫 성공(첫 점프 성공, 첫 적 처치)까지 몇 초인가. 30초를 넘기면 앞당긴다.
- 첫 죽음이 억울하지 않은가. 죽은 뒤 2초 안에 다시 플레이하는가.
- 로딩이 길면 첫인상이 거기서 끝난다. `engine perf` 의 `load_s` 를 본다. 웹은 3초 안쪽을 목표로.
- 타이틀 → 플레이까지 입력 한 번.
- 재생 결과에서 플레이어가 멈춰 있던 구간(입력이 없던 구간)이 헷갈린 곳이다.

## 4. 성능

```sh
$GF engine perf --seconds 10 --script bot/clear.json --out captures/perf/<이름>.json
$GF engine perf --seconds 10 --uncapped --out captures/perf/<이름>-uncapped.json    # 여유가 얼마나 있는지
```

- 평균이 아니라 **최악 프레임**을 본다. 가끔 튀는 것이 끊김으로 느껴진다.
- 드로우 콜이 많으면: 같은 재질 묶기, 인스턴싱, 스프라이트 아틀라스.
- 3D 생성 모델은 삼각형과 텍스처가 과하다. `$GF blender info <glb>` 로 세고 `$GF blender decimate <glb> --triangles <N>` 로 줄인다. 텍스처는 화면에서 보이는 크기에 맞춘다.
- 웹: 로딩 크기(모델·텍스처·오디오 합계)를 줄인다. 큰 시트는 나눈다. 로딩 화면에서 멈추지 않는지 `engine test` 의 콘솔 오류로 확인한다.
- 매 틱 객체를 새로 만드는 코드, 화면 밖 물체의 갱신을 찾는다.
- 고친 뒤 같은 명령으로 다시 재서 숫자로 비교한다. 느낌으로 "빨라졌다"고 하지 않는다.

## 5. 흔한 감점 요인 (공개 뒤 실제로 지적받는 것)

- 게임플레이 없이 걷기만 하는 화면
- 어색한 걷기 애니메이션, 미끄러지는 발
- 텍스처가 물체가 아니라 월드에 붙어 흐르는 것
- 브라우저가 죽거나 로딩에서 멈춤
- 타격에 반응이 없음(히트스톱·경직 없음)
- 어디서 본 듯한 UI, 기존 게임과 너무 닮은 화면

# gameforge 공통 규약

모든 `gf-*` 스킬이 따르는 규칙이다. 스킬 본문과 어긋나면 스킬 본문이 우선한다.

## 명령

스킬 문서의 `$GF` 는 아래 전체를 줄여 쓴 것이다. 셸 변수는 Bash 호출 사이에 남지 않으므로 실행할 때는 매번 전체를 쓴다. 하네스 경로는 각 SKILL.md 의 "명령" 절에 실제 값으로 적혀 있다.

```sh
uv run -q --project "<하네스>/tools" gf --project "<게임 폴더 절대 경로>" <group> <cmd> ...
```

한 번의 Bash 호출에서 여러 명령을 줄여 쓰려면 변수가 아니라 함수로 만든다. zsh 는 `GF="uv run ..."; $GF state show` 의 `$GF` 를 단어로 나누지 않아 "no such file or directory" 로 실패한다.

```sh
gf() { uv run -q --project "<하네스>/tools" gf --project "<게임 폴더 절대 경로>" "$@"; }; gf engine test; gf engine capture --out captures/<이름> --at 1
```

- 성공: 종료 코드 0, 표준 출력 마지막 줄이 `{"ok": true, "files": [...], ...}`. `files` 는 게임 폴더 기준 상대 경로다.
- 실패: 0 이 아닌 종료 코드와 `{"ok": false, "error": "..."}`. 오류를 그대로 읽고 원인을 고친다. 같은 명령을 인자만 바꿔 가며 반복하지 않는다.
- 플래그가 헷갈리면 추측하지 말고 `$GF <group> <cmd> --help` 로 확인한다.

## 결과를 보여 주는 방법

1. 결과 이미지는 Read 로 직접 열어 본다. 보지 않은 것을 "잘 나왔다"고 말하지 않는다.
2. 사용자에게는 **절대 경로**를 준다 (게임 폴더 + `files` 의 상대 경로). 사용자가 Orca/Paseo 나 Finder 에서 연다.
3. 본 것을 두세 줄로 말한다: 무엇이 보이는지, 기준과 어디가 다른지, 다음에 무엇을 할지.
4. 여러 장이면 `$GF post contact <폴더> --out <png>` 로 번호 붙은 모음판 한 장을 만들어 그것을 보여 준다.

## 승인

- 단계 순서: `plan → look → graybox → assets → polish → publish`. 지금 단계는 `$GF state show`.
- 단계를 넘기는 것은 사용자다. 결과물을 보여 주고 "이대로 다음 단계로 넘어갈까요?"를 묻고, 사용자가 그렇다고 한 뒤에만 `$GF state approve --note "<사용자가 승인한 내용 한 줄>"` 을 실행한다.
- 승인 명령은 훅이 `gf check evidence` 로 먼저 검사한다. 막히면 메시지가 말하는 근거를 만든다. 근거 파일을 손으로 만들거나 검사를 우회하지 않는다.
- 이전 단계로 돌아가야 하면 `$GF state set <단계>` 를 쓰고 이유를 사용자에게 말한다.

## 비용

- 생성(`gf gen ...`, `gf fal run`)은 돈이 든다. 처음 쓰는 종류는 `--dry-run` 으로 엔드포인트와 추정 비용을 먼저 본다.
- 추정 비용이 `null` 로 나오는 모델이 있다 (단가 단위가 tokens·credits·compute seconds 인 경우). 이런 호출은 그대로는 **거부된다.** `--estimate-usd <대략의 값>` 을 직접 주고(한도와 비교되고 기록에 남는다) `--max-usd` 로 한도를 건다. 금액을 전혀 모를 때만 `--allow-unknown-cost` 를 쓰고, 쓰기 전에 사용자에게 말한다. 실측 참고값: 룩 영상 4초 480p 약 $0.9, 3D 모델 1개 약 $0.5, 리깅 1회 $0.8, 스프라이트 영상 3초 약 $0.34, 이미지 1장 $0.08.
- 시험 호출은 가장 싼 설정으로 한다 (`--resolution 0.5K`, 짧은 `--duration`). 방향이 맞은 뒤에 해상도를 올린다.
- 한 번에 $1 이 넘는 호출, 같은 것의 세 번째 재생성은 실행 전에 사용자에게 금액을 말하고 확인받는다.
- 누적 지출은 `$GF state show` 의 `spent_usd` 다. 단계가 끝날 때 알려 준다.

## 하지 않는 것

- **특정 기존 게임을 재현하지 않는다.** 이름, 캐릭터, 아트, 음악, 레벨, 화면 구성을 따라 만들지 않는다. 장르 안에서 새 게임을 만드는 것은 괜찮다. 사용자가 "○○처럼"이라고 하면 그 게임에서 좋아하는 특성(속도감, 색, 카메라 거리 등)을 말로 뽑고 다른 출처의 특성과 섞는다.
- `.env` 를 읽거나 출력하지 않는다. 키가 있는지는 `$GF doctor` 의 `fal_key` 로 본다.
- `gf/gf_bridge.gd`, `gf/bridge.js`, `.gf/state.json`, `.gf/judge/` 를 손으로 고치지 않는다.
- 근거 없이 "됐다", "고쳤다"고 말하지 않는다. 말하기 전에 실행하고, 화면을 보고, 그 파일 경로를 함께 준다.
- 한 번에 여러 가지를 바꾸지 않는다. 하나 바꾸고 확인하고 다음으로 간다.
